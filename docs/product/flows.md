# 核心用户流程

**状态：Draft**

## 创建文章或草稿

1. 用户在 Hexo 工作区打开命令面板。
2. 选择“新建文章”或“新建草稿”。
3. 输入标题，必要时选择布局或文章目录。
4. 扩展根据站点配置生成文件名、文章目录和 Front Matter。
5. 创建对应的文章资源目录（如果站点启用了文章资源目录）。
6. 打开新文件，并把光标放在正文区域。

失败时应说明：未找到 Hexo 站点、无法确定文章目录、文件已存在，或目标路径不可写。

## 粘贴图片

1. 用户打开并保存一篇位于 Hexo 文章目录中的 Markdown 文件。
2. 用户复制截图或图片文件，并在编辑器中执行普通粘贴，或使用扩展的“粘贴图片”命令。
3. 扩展判断剪贴板内容是否包含支持的图片；如果是普通文本，交给 VS Code 默认粘贴流程。
4. 扩展识别站点根目录、当前文章和资源策略。
5. 扩展生成不冲突的文件名，并把图片写入文章资源目录。
6. 图片写入成功后，在光标位置插入 Hexo 可解析的图片引用。
7. 扩展提示保存位置，并保持光标位于插入内容之后。

任何一步失败时，都不能留下只存在于 Markdown 中的悬空引用；如果图片已经写入但插入失败，要提供清理或重试信息。

## 本地预览

1. 用户在 Hexo 工作区执行“启动预览”。
2. 扩展检查站点依赖和 Hexo 命令是否可用。
3. 扩展启动本地 Hexo server，并打开预览地址。
4. 用户可以从命令面板停止当前预览进程。

MVP 不自动修改站点依赖，也不自动执行生产发布。

## 关键错误状态

| 场景 | 行为 |
| --- | --- |
| 当前文件不是 Markdown | 不接管普通粘贴 |
| 工作区不是 Hexo 站点 | 提示用户选择或打开 Hexo 工作区 |
| 当前文章未保存 | 要求先保存，避免无法推导路径 |
| 找不到文章资源目录 | 根据配置创建，或提示用户开启资源目录 |
| 文件名冲突 | 自动添加序号或时间后缀，不覆盖原文件 |
| 图片写入失败 | 不插入引用，显示具体路径和权限错误 |
| 当前已有其他图片粘贴扩展 | 提供命令或 Paste As 入口，避免静默抢占普通 Ctrl+V |
