# 待确认问题

**状态：Waiting for product decisions**

下面的问题会影响 MVP 的行为，建议在开始实现前确认。文档中的“暂定默认方案”可以作为默认答案。

## 1. 图片引用格式

你希望插件默认插入哪种格式？

- **方案 A（建议）**：根据 Hexo 配置生成普通 Markdown 图片引用；配置不足时提示用户。
- **方案 B**：始终生成 `{% asset_img filename alt %}`，稳定但 Markdown 在普通预览器中不一定能显示。
- **方案 C**：提供设置项，由用户选择普通 Markdown 或 `asset_img`。

## 2. 文章目录策略

MVP 是否只支持标准 Hexo 目录：

```text
source/_posts/
source/_drafts/
```

还是第一版就需要支持站点配置中的自定义 `new_post_name`、自定义草稿目录和多根工作区？建议先支持标准目录，把自定义目录作为 P1。

## 3. Ctrl+V 行为

是否接受以下策略：

- 普通文本继续使用 VS Code 默认 Ctrl+V；
- 只有剪贴板包含图片时才由扩展提供图片粘贴动作；
- 另外提供一个显式的“Hexo Workbench: Paste Image”命令作为稳定后备入口。

## 4. 新建文章时的 Front Matter

第一版需要哪些字段？建议默认只生成：

```yaml
---
title: 文章标题
date: 2026-09-11 00:00:00
tags:
categories:
---
```

还是要直接适配你当前博客的完整字段模板？如果要适配模板，建议使用工作区配置文件，而不是把 Tessera 的字段写死在扩展中。

## 5. Git 和发布

建议 MVP 不自动 commit 或 push，只负责编辑文件。Git 操作可以在 P1 以显式命令加入。这样不会因为一次粘贴图片就产生不可预期的远程变更。

## 6. 第一批验收方式

建议用一个真实 Hexo 测试博客验收以下路径：

1. 新建一篇文章；
2. 粘贴 Windows 截图；
3. 粘贴浏览器复制的图片；
4. 粘贴同一张图片两次；
5. 在首页、归档页和文章页检查图片；
6. 创建草稿并预览；
7. 在非 Hexo Markdown 项目中确认普通粘贴没有被破坏。
