# Hexo Workbench 产品简报

**状态：Accepted**
**版本：0.2**
**更新时间：2026-09-11**

## 一句话定位

Hexo Workbench 是一个面向个人 Hexo 作者的 VS Code 写作环境，让用户在保留 Markdown、文件资源和 Git 工作流的前提下，舒适地创建文章、处理图片并预览博客。

## 要解决的问题

Hexo 的发布结果稳定、成本低，也适合长期维护，但写作过程需要用户手动处理一组与内容无关的工作：

- 手动创建文章文件和 Front Matter；
- 手动创建或寻找文章对应的图片目录；
- 从剪贴板粘贴图片时，图片文件没有自动落到正确位置；
- 图片链接容易使用本机绝对路径，或者使用了 Hexo 无法在首页、归档页正确解析的相对路径；
- 预览、草稿和正式文章之间缺少连续的操作路径。

用户不希望为此维护一套数据库、后台服务器和图片服务，也不希望被某个主题或云平台锁定。

## 目标用户

第一阶段只服务于以下用户：

- 使用 VS Code 在本地写作；
- 使用 Hexo 生成博客；
- 文章和图片通过 Git 保存；
- 主要由个人维护一个或少量博客站点；
- 接受 Markdown 和命令行工具，但希望减少重复操作。

## 产品原则

1. **本地优先**：文章、图片和配置保存在用户工作区，不要求在线账户或自建后端。
2. **Hexo 感知**：理解 Hexo 的站点目录、文章资源目录、草稿和 Front Matter，不只是做通用 Markdown 操作。
3. **文件透明**：所有自动操作都能在文件树和编辑器中看见，不把内容藏在扩展私有数据库里。
4. **主题无关**：不绑定 Tessera；只依赖 Hexo 本身和用户站点配置。
5. **渐进增强**：普通 Markdown 编辑仍然可用，扩展失效时不能破坏文章文件。
6. **安全可恢复**：写入前检查目标路径，避免覆盖同名资源；失败时不插入悬空链接。

## MVP 范围

### P0：必须完成

- 识别当前 VS Code 工作区是否为 Hexo 站点；
- 创建文章和草稿，并生成可配置的 Front Matter；
- 通过站点根目录 `.hexo-workbench.yml` 提供默认模板和自定义字段；
- 在文章中粘贴或拖入图片；
- 根据当前文章定位文章资源目录；
- 生成不会依赖本机绝对路径的图片引用；
- 用户可选择普通 Markdown 或 Hexo `asset_img` 格式，支持工作区默认值和单次粘贴选择；
- 文件名冲突时自动改名，不覆盖已有文件；
- 文本粘贴保持 VS Code 原有行为；
- 对非 Hexo 工作区、未保存文章、资源写入失败给出明确提示；
- 完成核心逻辑的自动化测试和手动验收说明。

### P1：第一版稳定后加入

- 启动和停止 Hexo 本地预览；
- 在当前文章和草稿之间切换；
- 识别和提示未使用的文章图片；
- 重新命名图片并同步更新引用；
- 支持多根工作区中的多个 Hexo 站点。

### 产品范围之外

- 在线 CMS、账号体系和云端数据库；
- 自建图片图床或第三方图片上传；
- 替代 VS Code 的完整 WYSIWYG 编辑器；
- 主题配置编辑器；
- Git 管理（包括 commit、pull、push）和部署/发布功能；这些由用户已有的 Git 工具、hook 和部署流程负责；
- 自定义文章目录、草稿目录和 `new_post_name` 路径模板；只支持标准 `source/_posts` 与 `source/_drafts`；
- 针对某个主题定制界面。

## 核心成功标准

- 用户在一篇已保存的 Hexo 文章中粘贴图片后，不需要打开文件管理器或手动改路径；
- 生成的图片文件和 Markdown 引用都在当前 Git 工作区内；
- 文章在正文页、首页摘要和归档页中都能正确显示图片；
- 普通文本、代码和 URL 的粘贴行为不被破坏；
- 用户可以不使用扩展的云服务，直接用现有 Hexo 命令完成预览和生成。

## 已确认方案

- 图片默认存放在当前文章对应的 post asset folder；
- 图片格式由用户选择；工作区默认值为 Markdown，用户可切换为 `asset_img`，插件不能因配置不足静默改用另一格式；
- Markdown 方式需要校验渲染器及 `post_asset_folder`、`marked.prependRoot`、`marked.postAsset` 等条件，并提示不兼容原因；
- 图片文件名默认使用可读的时间戳，并处理重名；
- 图片命名格式支持全局设置，并可由工作区配置覆盖；
- 所有写入都使用 VS Code workspace API，并在插入引用前确认文件写入成功；
- 首个版本使用命令面板和编辑器上下文命令，不先做复杂侧边栏。

## Front Matter 工作区模板

`.hexo-workbench.yml` 由用户显式初始化，随站点保存；不存在时使用内置默认值。字段清单采用 Hexo 官方支持的 `layout`、`title`、`date`、`updated`、`comments`、`tags`、`categories`、`permalink`、`excerpt`、`disableNunjucks`、`lang`、`published`，不内置主题专用字段。[官方字段说明](https://hexo.io/docs/front-matter)

默认生成 `title`、`date`、`tags`、`categories`；其余官方字段可按需加入，避免覆盖 Hexo 的自动默认行为。用户可以替换默认模板、覆盖值、添加任意 YAML 字段。标题和日期只做受限占位符替换，不执行模板代码；改变模板不回写已有文章。

## 验收安排

开发阶段负责自动化测试、隔离的 Hexo 测试站点和 VSIX 打包。功能实现后提供真实博客验收清单，由维护者在自己的博客测试；验收完成前功能分支不合并到 `main`。
